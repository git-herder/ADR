# ADR-26110802: Требования к качеству кода application

## Статус

✅ **Принято**

## Контекст

В репозитории `application/` появляется первый прикладной код Git Herder.
[ADR-26110801][adr-layout] задаёт компоновку пакетов, но не локализует текст в
терминале, язык комментариев и порог покрытия тестами. В [DoD playbook][dod] для
команд зафиксировано **не менее 70%** покрытия по строкам; для единственного
продукта CLI команда хочет более строгий порог до первой поставки.

Документация спецификаций для людей — на русском; терминальный интерфейс утилиты
и open-source аудитория предполагают **английский** пользовательский вывод.

## Решение

Правила ниже обязательны для всего Go-кода в репозитории `application/`.

### Покрытие тестами

- Суммарное **покрытие по строкам (line coverage) не ниже 80%** по пакетам `./...`
  (`internal/`, `cmd/`).
- Контроль: `go test ./... -coverprofile=coverage.out` и проверка порога (например,
  цель `covercheck` в `Makefile` репозитория `application/`).
- Порог **80%** действует **только** для `application/` и **не** меняет [DoD][dod]
  для остальных репозиториев workspace.

### Заголовок каждого исходного файла

- У каждого файла `*.go`, **кроме** `*_test.go`, в начале файла (непосредственно
  перед объявлением `package`) — многострочный комментарий **на русском языке**:
  назначение файла и кратко, что в нём происходит (аналог package documentation).

### Комментарии в коде

- Все комментарии в исходниках, включая godoc к экспортируемым символам (если
  нужны), — **на русском**.

### Вывод в консоль

- Весь текст, который **видит пользователь** в терминале, — **на английском**:
  сообщения об ошибках и предупреждения через pterm, подсказки, тексты команд и
  флагов Cobra (`--help`), строка `githerd version <semver>`.
- Поля `message` в журнале (`slog`) / TSV на stderr для событий, дублируемых
  пользователю (например, предупреждение о битом `default`), — **на английском**.
- **Исключения:** машиночитаемый вывод не локализуют — перечень имён профилей на
  stdout; содержимое YAML после remarshal у `profile show` (данные, не UI).

Разделение pterm (пользователь) и slog (журнал) — [ADR-26101701][adr-stack].

### Remarshal YAML

Вывод `profile show` через parse → маскировка → serialize может удалить комментарии
в YAML; это согласовано со [спекой команды profile][profile-spec] (remarshal).

## Аргументация

| Альтернатива | Почему не выбрана |
| ------------ | ----------------- |
| Единый порог 70% из DoD | Осознанно строже для единственного CLI до первого релиза |
| Русский UI в терминале | Ограничение принято для OSS и единообразия `--help` |
| Английские комментарии в коде | Команда и спеки на русском; код сопровождают авторы из той же среды |
| Исключение `main.go` из порога 80% | Нет; `main` только делегирует в bootstrap |

## Последствия

### Позитивные

- Предсказуемый язык для пользователя и контрибьюторов.
- Высокий порог регрессии на старте продукта.

### Негативные

- Расхождение: спеки на русском, `--help` на английском.
- Дополнительные тесты для удержания 80% на каждом MR в `application/`.

### Компромиссы

- CI-гейт по покрытию может появиться позже; локальный `Makefile` — минимум на
  первой поставке.
- Жёсткая проверка языка комментариев линтером **не** вводится в этом ADR.
