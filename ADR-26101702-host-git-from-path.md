# ADR-26101702: Git с хоста из PATH

## Статус

✅ **Принято**

## Контекст

[Git Herder][product-intent-readme] работает с локальными копиями и git-репозиториями.
Нужно решить, **как** выполнять git-операции: свой код в бинаре утилиты или внешний
`git`.

Целевой пользователь уже ставит git для ежедневной работы. Без git массовые сценарии
продукта не имеют смысла.

Связанный выбор стека CLI и окружения: [ADR-26101701-go-application-stack][adr-stack].

## Решение

Локальные операции с репозиториями выполняем через **установленный на хосте `git` из
`PATH`**: запускаем процесс `git`, а не встраиваем реализацию Git в бинарь Git Herder.

- В зависимости Git Herder **не** добавляем go-git и аналоги «ради git».
- **Не** поставляем и **не** встраиваем `git` вместе с утилитой.

Минимальную версию `git` на хосте и проверку при старте задаём в прикладной
спецификации, не в этом ADR.

## Аргументация

| Вариант | Почему отказались |
| ------- | ----------------- |
| go-git и другие Git-библиотеки на Go | Лишний вес при гарантированном `git` у пользователя; поведение и версия расходятся с его установкой и настройками |
| Встраивание или поставка `git` с Git Herder | Дублируем то, что пользователь уже имеет; не наша зона ответственности |
| Жёсткий путь к одному бинарю вне `PATH` | Хуже переносимость; `PATH` — обычный способ найти `git` на машине разработчика |

## Последствия

### Позитивные

- Меньше зависимостей в бинаре Git Herder.
- Локальные операции ведут себя так же, как у пользователя в терминале.
- Проще объяснить отладку: те же команды `git`, что он уже знает.

### Негативные

- На машине без `git` в `PATH` утилита не работает — осознанное ограничение
  аудитории.
- Разные версии и конфигурация `git` на хостах — диагностика и документация, не
  единый встроенный рантайм.

### Компромиссы

- Ошибки и возможности зависят от версии `git` пользователя; политику поддержки
  версий фиксируем в спецификации, не здесь.
